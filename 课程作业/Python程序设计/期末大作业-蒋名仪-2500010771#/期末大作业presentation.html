2.3海报视觉：为什么需要图像信息？Visual Side-Info
核心问题

协同过滤只看"谁给哪部电影打了几分"，完全忽略电影的视觉风格。然而海报的色调、构图、人物排布是稳定的风格信号。

对于几乎没人评分的冷门电影，协同过滤的潜因子 \(\mathbf{q}_i\) 根本学不到——评分太少。但海报特征始终可用。

解决思路

把海报视觉向量 \(\tilde{\mathbf{v}}_i\) 注入 SVD：即使 \(\mathbf{q}_i\) 学不动，\(W\tilde{\mathbf{v}}_i\) 仍提供非零信号，缓解冷启动。

M6 VisSVD 公式
$$\hat{r}_{ui} = \mu + b_u + b_i + \mathbf{p}_u^T\!\left(\mathbf{q}_i + W\tilde{\mathbf{v}}_i\right)$$

\(\tilde{\mathbf{v}}_i\)：海报经 ResNet-50 提取 512 维特征后 PCA 降至 64 维

\(W\)：可学习的视觉→潜空间投影矩阵

\(\mathbf{q}_i\)：自由潜因子（协同）；冷门电影 \(\mathbf{q}_i \approx 0\) 时 \(W\tilde{\mathbf{v}}_i\) 兜底

实现流程

Step 1   ResNet-50 抽 512 维海报特征 → 缓存

Step 2   PCA 降到 64 维去噪；余弦相似度建 Visual Item-KNN (M5)

Step 3   将 \(\tilde{\mathbf{v}}_i\) 注入 FunkSVD，联合训练 \(W\) (M6)

Step 4   按电影流行度分桶，单独考察冷门电影增益

全量开放测试集 MSE

M5 Visual-KNN = 1.3373（纯视觉，无协同，较差）

为什么全量 MSE 提升不大？

视觉 side-info 只在冷门电影（评分 < 100 条）上 RMSE 降低明显。但冷门电影仅占测试集 0.6%，加权到全量后被严重稀释。

热门电影的协同信号已经足够强，额外的视觉信号边际贡献被稀释。

结论

→ 典型的 "side-info 只在稀疏区域有效"

这是结构性的，不是方法写错了。视觉特征的价值在于缓解冷启动，而非提升全量精度。

2.4LLM 背景知识：用"世界知识"补充协同Content Residual
核心问题

ratings 表只有行为信号——谁打了几分。缺少电影的"世界知识"：口碑评价、主题风格、奖项、情绪基调。

这些信息恰好存在于 LLM 的训练语料和文本语义中。

双路径设计

路径 A — 在线 LLM：DeepSeek API 返回 online_rating / themes / award_level / sentiment，结构化为数值特征。

路径 B — 本地 MiniLM：把 name + intro + 导演 + 主演编码成 384 维语义向量，作为 API 不可用时的 fallback。

M7 内容残差模型公式
$$\hat{r}_{ui} = \hat{r}_{ui}^{\,M2+} + g_\theta(c_i,\, u_u)$$

\(c_i\)：电影内容特征（LLM 知识 \(\oplus\) MiniLM 句向量）

\(u_u\)：用户人口学特征（年龄、性别、职业）

\(g_\theta\)：LightGBM 学习"基线 M2+ 没拟合到的残差"

LightGBM 自动捕捉交叉项（如"学生 × Comedy"）

为什么用残差而非直接预测？

协同基线 M2+ 已经拟合了大部分评分模式。内容特征只需要学基线遗漏的部分，避免从头拟合，降低过拟合风险。

2.5Stacking：如何协同四个专家？Stacking
核心问题

四个专家（M3 协同、M2+ 偏置、M6 视觉、M7 内容）各有所长，但单看全量 MSE 看不出差异——因为在不同场景（冷门/热门/稀有 genre）下优势不同。

解决思路

Stacking 元学习：用一个 Ridge 回归器学一组全局权重 \(\boldsymbol{\alpha}\)，把四个专家的预测线性组合。

Stacking 公式
$$\hat{r}^{\text{Stack}} = \alpha_0 + \boldsymbol{\alpha}^T \mathbf{z}$$ $$\mathbf{z} = (\hat{r}^{M3},\ \hat{r}^{M2+},\ \hat{r}^{M6},\ \hat{r}^{M7})$$
$$\boldsymbol{\alpha} = \arg\min_{\alpha}\; \|\mathbf{y} - \alpha_0\mathbf{1} - Z\boldsymbol{\alpha}\|^2 + \lambda\|\boldsymbol{\alpha}\|^2$$

\(\mathbf{z}\)：四模型预测拼成的 4 维向量；\(\boldsymbol{\alpha}\)：Ridge 学到的权重

防泄漏：用训练集再切一折 meta-val 学 \(\boldsymbol{\alpha}\)，不碰测试集

场景分桶实测（基座训练充分后）

冷门电影 → M6 VisSVD 略优（视觉兜底）

稀有 genre / 热门头部 → M3 最优（协同最强）

M2+ / M7（人口学/内容）全场景被压制

为什么外部信息被压制？

基座 M3 训练充分后，行为协同信号已经足够强。人口学和内容特征提供的信息与协同高度冗余（M3 与 M6 预测相关性 0.98），难以带来额外增益。

2.5Stacking 结果：强相关专家集成增益有限Results
关键数值

M3 FunkSVD（单模型） = 0.7144

Stacking（4 专家线性组合） = 0.7386

SegmentBlend（分场景最优混合） = 0.7132

Stacking 权重揭示了什么？

Ridge 学到的权重：M3 = 1.86, M2+ = −0.849, M6 = −0.277, M7 = 0.282

M3 权重远超其他 → 元学习器几乎只信 M3。M2+ 甚至是负权重（被 M3 压制后，反而引入噪声）。

结论

全局 Stacking 反而略差于 M3 单模型

原因：当专家之间高度相关时（相关性 0.98），线性组合容易 meta 过拟合。集成要有真增益，专家必须"错在不同地方"。

→ 见反思页：集成要"去相关"才有效

2.6 ①异常用户：如何定义？画像是什么？Anomaly Profile
异常定义（残差阈值法）
$$e_{ui} = r_{ui} - \hat{r}_{ui}^{M3},\quad \text{异常样本} \Leftrightarrow |e_{ui}| > 1.5$$
$$\text{异常用户} = \text{评分数}\geq 30\text{的用户中},\;\overline{|e_u|}\;\text{排名前 5\%}$$

\(e_{ui}\)：M3 预测残差；\(\overline{|e_u|}\)：用户级平均绝对残差

异常样本 ≈ 4.57%；异常用户 = 260 人

为什么这些人"异常"？

评分习惯个性化（过严/过松/口味偏窄），全局 M3 难以拟合 → 残差被放大。

2.6 ③异常用户定向优化：效果与反思Targeted Calibration
思路：不动正常用户，只校准异常用户
方法一：重估用户偏置
$$b_u^* = \frac{\displaystyle\sum_{i \in I(u)}\left(r_{ui} - \mu - b_i\right)}{|I(u)| + \lambda_u}$$

固定 \(b_i\)，只用用户自己的残差收缩估计 \(b_u^*\)

方法二：簇专属专家融合
$$\hat{r}_{ui} = \sum_k w_{g(u),k}\;\hat{r}_{ui}^{(k)},\quad \mathbf{w}_g = \mathrm{softmax}\!\left(-\frac{\mathrm{MSE}_g}{\tau}\right)$$

\(g(u)\)：用户所属簇；按各专家在该簇的误差学权重

Fig 2.6c — 异常用户定向优化效果
结果

异常用户 MSE：1.342 → 1.344（基本持平）

基座训练充分后，异常用户误差已是不可约噪声，后处理无效。

价值在于"识别 + 分流"，而非强行校准。

2.7MOE：按样本动态选专家Mixture of Experts
核心问题

Stacking 给所有样本同一组权重。但 2.5/2.6 已经显示：不同场景、不同用户，该信的专家不同。

能不能让模型自动看当前样本属于哪种场景，动态分配权重？

MOE 公式
$$\hat{r}_{ui} = \sum_k \pi_k(\mathbf{x}_{ui};\theta)\;\hat{r}_{ui}^{(k)},\quad \sum_k \pi_k = 1$$
$$\boldsymbol{\pi} = \mathrm{softmax}\!\left(W_2\;\mathrm{ReLU}(W_1\mathbf{x} + b_1) + b_2\right)$$

\(\pi_k\)：第 \(k\) 个专家的 softmax 权重（样本级动态）

\(\mathbf{x}_{ui}\)：上下文特征；专家参数固定，只训练 gating 网络

与 Stacking 的关键区别

Stacking = 全局固定权重 \(\boldsymbol{\alpha}\)（一组权重用于所有样本）

MOE = 按样本动态权重 \(\boldsymbol{\pi}(\mathbf{x})\)（软路由）

Router 输入特征

用户评分数 / 均值 / 方差

电影热度、冷启动标志、稀有 genre 标志

异常用户簇 one-hot

→ 让路由"知道"当前样本属于哪种场景，自动选最合适的专家。

2.7MOE 结果：为什么 MOE ≈ M3？Results
关键结果

MOE 开放 MSE = 0.7143

（4 experts：M3 / M2+ / M6 / M7）

对比 M3 = 0.7144 — 几乎相同

路由权重分析

M3/M6 训练充分后全面占优，router 收敛到几乎只用 M3（权重 ≈ 0.99）。

这不是 MOE 的失败——恰恰是 MOE 的正确行为：当某专家在所有场景都更优时，理性的路由器自动归一到它。

结论

MOE 的动态路由比 Stacking 的固定权重更合理

但在"一家独大"的专家格局下，动态路由没有发挥空间。要让 MOE 有真增益，需要专家之间能力更互补。

3.1MiniLM 语义替代 TF-IDF 预测电影类型Genre Prediction
核心问题

期中用 TF-IDF 词袋做类型预测，丢了词序与上下文语义（如反讽、隐喻）。改用预训练 transformer 的语义表示。

为什么用冻结 encoder + 浅头？

数据仅 ~2k 部电影。全微调 transformer 容易过拟合。冻结 MiniLM-L6（22M 参数，6 层）抽 384 维句向量，只训练一个浅分类头，参数量少且训练快。

公式
$$\mathbf{z}_i = \text{MiniLM}(\text{intro}_i) \in \mathbb{R}^{384}$$
$$F\text{（线性头）}: \hat{y} = \sigma(W\mathbf{z}_i + b)$$
$$G\text{（MLP 头）}: \hat{y} = \sigma\!\left(W_2\;\text{ReLU}(W_1\mathbf{z}_i) + b\right)$$

\(\sigma\)：sigmoid（逐 genre 独立输出 0/1）

损失函数：BCEWithLogitsLoss（多标签二分类）

评测指标（多标签）

Hamming loss · Jaccard · F1-macro · F1-samples · Subset accuracy

3.1MiniLM 结果：语义表示稳定提升Results
横向对比

B   LR-OVR (TF-IDF)：F1-samples = 0.4751

F   MiniLM + Linear 头：F1-samples = 0.5054

G   MiniLM + MLP 头：F1-samples = 0.5599

逐级提升的原因

TF-IDF → MiniLM：从关键词匹配升级到语义理解。"a man struggles with his past" 在 TF-IDF 里只有词频，在 MiniLM 里编码了"挣扎/过去/内心冲突"的语义。

Linear → MLP：genre 之间有非线性关系（如 Action + Sci-Fi 常共现），MLP 能捕捉这些交互模式，线性头不行。

结论

MLP 头 > 线性头 > TF-IDF 基线

语义表示 + 适当的分类头 = 小数据多标签的最佳实践。

3.2LDA 主题 × 年龄：哪些偏好随年龄变化？Topic × Age
核心问题

genre 是离散标签（Action / Drama / …），但语义主题更细粒度。用 LDA 从电影简介中抽取"语义主题"，研究哪些主题偏好随年龄显著变化。

Top 年龄敏感主题

t1：love, man, falls, woman, young（爱情/青春）

t2：war, world, ii, group, evil（战争/历史）

t5：new, life, york（都市/生活）

结论

各主题评分都随年龄升高 → 年长用户打分更宽容

战争/历史主题的年龄梯度最陡，都市/爱情相对平缓。

公式
$$\boldsymbol{\pi}_d \in \Delta^{K-1}\quad\text{（电影 }d\text{ 的 LDA 主题分布）}$$
$$\text{discrim}_k = \frac{1}{|A|}\sum_a \left(\bar{r}_{ka} - \bar{r}_k\right)^2$$

\(\bar{r}_{ka}\)：年龄段 \(a\) 对主题 \(k\) 的加权平均评分；按 discrim 挑 top-3

3.3LLM 高维嵌入：进一步提升类型预测LLM Embedding
核心问题

3.1 用 MiniLM（384 维），是通用小模型。能否换成大模型句嵌入（1536 维），利用更广泛的语料和更丰富的语义？

结果

G MiniLM+MLP：F1-samples = 0.5599

H LLM-emb+MLP：F1-samples = 0.6347

结论

高维语义嵌入 + 适当正则 → 冻结方案最优

但嵌入是"冻结"的——能否让模型针对电影分类任务端到端学习？→ 3.4 BERT 微调

公式
$$\mathbf{z}_i^{\text{LLM}} = \text{Embed\_API}(\text{intro}_i) \in \mathbb{R}^{1536}$$
$$H: \hat{y} = \sigma\!\left(\text{MLP}_{256}(\mathbf{z}_i^{\text{LLM}})\right)$$

1536 维 → 256 隐层 MLP → sigmoid 多标签输出

维度高 → Dropout = 0.4 + weight decay 抑制过拟合

3.4BERT 端到端微调：让语义表示针对任务学习Fine-tuning
核心思路

之前的方案（MiniLM / LLM-emb）都是冻结嵌入 + 训练浅头——预训练模型不了解"电影类型"这个任务。

端到端微调：让 DistilBERT 的 6700 万参数全部 针对电影分类任务更新。

结果对比

H LLM-emb+MLP (冻结 1536 维)：F1 = 0.6347

I BERT-finetune (端到端 67M)：F1 = 0.6160

分析

DistilBERT（67M 参数，768 维）微调 4 epoch 已接近冻结 LLM 1536 维方案。CPU 限制了训练轮数；更多 epoch 或用 GPU 可进一步提升。

公式
$$I: \hat{y} = \sigma\!\left(W_c \cdot \text{ReLU}(W_p \cdot \text{BERT}_{\theta}(\text{intro}_i)_{[\text{CLS}]})\right)$$

\(\theta\) 端到端更新，lr = 2e-5，4 epochs，CPU 训练 ~95 min

关键发现最大杠杆：把基座 SVD 训练充分Key Finding
发现了什么？

原始 FunkSVD 实现每 epoch 仅采样 ~32% 数据进行梯度更新 → 严重欠拟合。

改为全量向量化 mini-batch SGD，纯 CPU，FunkSVD ≈ 35s，VisSVD ≈ 3min。

效果

M3 MSE：0.823 → 0.714   ↓ 13.2%

异常用户 MSE：1.69 → 1.34

这一步的提升，远超海报/LLM/Stacking/MOE 全部叠加（~1%）之总和。

为什么这才是关键？

所有 side-information 只在协同信号不足时有用。如果基座本身就没训练好，side-info 看起来"有效"——实际上只是在弥补基座的欠拟合。

一旦基座训练充分，side-info 的边际贡献几乎消失。

核心 Takeaway

主瓶颈是基座是否训练充分，不是缺信息

反思为什么新增信息对全量 MSE 提升有限？Diagnosis
根因一：新增信息与协同高度冗余

M3 与 M6 预测相关性 0.98。冷门电影仅占测试集 0.6%，冷用户 0%——side-info 只在极少数稀疏样本有用，加权到全量后被严重稀释。

根因二：误差已接近不可约噪声地板

同一用户对同类电影评分波动大。M3 = 0.714 已逼近该数据的可预测性极限。

根因三：集成 / 后处理天然增益小

M2+/M7 全面被 M3 压制；Stacking = 0.7386 反而 > M3（meta 过拟合）；异常后处理持平。

这些是结构性原因：行为信号足够强、基座充分训练后，外部信息边际收益天然很小。
