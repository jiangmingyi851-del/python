ST 表（Sparse Table，稀疏表）是一种专门用于解决 **可重复贡献问题**（如区间最小值、最大值、最大公约数等）的静态数据结构。它的核心思想是 **倍增预处理 + 区间重叠覆盖**。下面我将从零开始，逐步拆解它的构建原理、步骤以及为什么它能做到 O(1) 查询。

---

## 一、ST 表要解决什么问题？

给定一个长度为 `m` 的数组 `A`（在我们的 LCA 问题中，`A = depth_seq`），我们要快速回答形如：**求区间 `[L, R]` 中最小值的下标（或最小值本身）** 的询问。

ST 表的限制：  
- **静态**：数组建好后不再修改。  
- **查询必须满足可重叠性**：即 `min(A[L..R])` 可以由两个**有重叠**的子区间的 `min` 合并得到（例如 `min(A[L..X], A[Y..R])` 其中 `X >= Y` 也可以）。这恰恰是 `min` 运算的性质。

---

## 二、核心思想：倍增预处理

我们预先计算 **所有长度为 2 的幂次的子区间的最小值位置**。

### 定义状态
`st[k][i]` ：从下标 `i` 开始，长度为 `2^k` 的区间内，**深度最小值的下标**（即 `depth_seq` 中最小值的位置）。

- `k` 的取值范围：`0 ≤ k ≤ ⌊log₂(m)⌋`，其中 `m` 是数组长度。
- `i` 的取值范围：`0 ≤ i ≤ m - 2^k`，保证区间不越界。

例如：
- `st[0][i]` 就是区间 `[i, i]`（长度为 1）的最小值下标，显然就是 `i` 本身。
- `st[1][i]` 是区间 `[i, i+1]` 的最小值下标。
- `st[2][i]` 是区间 `[i, i+3]` 的最小值下标。

### 递推公式（状态转移）

一个长度为 `2^k` 的区间 `[i, i + 2^k - 1]` 可以平分成两个长度为 `2^(k-1)` 的子区间：

- 左半部分：`[i, i + 2^(k-1) - 1]`，对应 `st[k-1][i]`。
- 右半部分：`[i + 2^(k-1), i + 2^k - 1]`，对应 `st[k-1][i + 2^(k-1)]`。

由于 `min` 运算允许重叠，整个区间的最小值就是这两个子区间最小值的 **较小者**。

写成递推式：
```
st[k][i] = argmin( st[k-1][i], st[k-1][i + 2^(k-1)] )
```
即比较 `depth_seq[ st[k-1][i] ]` 和 `depth_seq[ st[k-1][i + 2^(k-1)] ]`，将深度更小的那个下标赋给 `st[k][i]`。

## 三、预处理步骤详解（以具体数组为例）

假设我们有 `depth_seq = [0, 1, 0, 1, 0]`（对应之前的欧拉序列例子）。`m = 5`。

### 1. 初始化第 0 层（k=0）
`st[0][i] = i`（每个长度为1的区间，最小值下标就是它自己）。

| i     | 0   | 1   | 2   | 3   | 4   |
| ----- | --- | --- | --- | --- | --- |
| st[0] | 0   | 1   | 2   | 3   | 4   |

### 2. 计算第 1 层（k=1，区间长度 2）
- `i=0`：区间 `[0,1]`，比较 `depth[0]=0` 和 `depth[1]=1` → 取下标 0。`st[1][0] = 0`。
- `i=1`：区间 `[1,2]`，比较 `depth[1]=1` 和 `depth[2]=0` → 取下标 2。`st[1][1] = 2`。
- `i=2`：区间 `[2,3]`，比较 `depth[2]=0` 和 `depth[3]=1` → 取下标 2。`st[1][2] = 2`。
- `i=3`：区间 `[3,4]`，比较 `depth[3]=1` 和 `depth[4]=0` → 取下标 4。`st[1][3] = 4`。
- `i=4`：区间 `[4,5]` 越界，不计算。

结果：
| i     | 0   | 1   | 2   | 3   | 4   |
| ----- | --- | --- | --- | --- | --- |
| st[1] | 0   | 2   | 2   | 4   | -   |

### 3. 计算第 2 层（k=2，区间长度 4）
- `i=0`：区间 `[0,3]`（左 `[0,1]` 下标 `st[1][0]=0`，右 `[2,3]` 下标 `st[1][2]=2`）。比较 `depth[0]=0` 和 `depth[2]=0`，任取一个（例如取 0）。`st[2][0] = 0`。
- `i=1`：区间 `[1,4]`（左 `[1,2]` 下标 `st[1][1]=2`，右 `[3,4]` 下标 `st[1][3]=4`）。比较 `depth[2]=0` 和 `depth[4]=0` → 取 2。`st[2][1] = 2`。
- `i=2`：区间 `[2,5]` 越界，停止。

最终 ST 表（只列出有效值）：

| k\i | 0   | 1   | 2   | 3   | 4   |
| --- | --- | --- | --- | --- | --- |
| 0   | 0   | 1   | 2   | 3   | 4   |
| 1   | 0   | 2   | 2   | 4   |     |
| 2   | 0   | 2   |     |     |     |

## 四、查询步骤：O(1) 的神奇之处

现在给定查询区间 `[L, R]`，我们如何用 ST 表在 **O(1)** 时间内得到最小值下标？

### 1. 计算区间长度对应的最大 `k`
取 `k = floor(log₂(R - L + 1))`，即长度二进制表示的最高位。
例如 `R - L + 1 = 5`，`log₂(5) ≈ 2.32`，`k = 2`。

### 2. 用两个长度为 `2^k` 的区间覆盖 `[L, R]`
由于 `2^k ≤ length`，且 `2^(k+1) > length`，因此我们可以用两个 **可能重叠** 的长度为 `2^k` 的区间完全覆盖目标区间：
- 第一个区间从 `L` 开始：`[L, L + 2^k - 1]`
- 第二个区间结束于 `R`：`[R - 2^k + 1, R]`

这两个区间的并集 **恰好** 是 `[L, R]`（允许中间重叠）。

### 3. 取两者最小值
```
left_min_idx = st[k][L]
right_min_idx = st[k][R - (1 << k) + 1]
answer = min(left_min_idx, right_min_idx)   # 比较 depth_seq 值
```

### 为什么重叠没关系？
因为 `min` 是幂等运算：`min(a,b,c) = min( min(a,b), min(b,c) )`。重叠部分 `b` 被计算两次不影响最终结果。

### 举例：查询区间 `[1, 4]`（长度 4）
- `length = 4`，`k = log₂(4) = 2`。
- 左区间：`st[2][1]`，右区间：`st[2][4 - 4 + 1] = st[2][1]`（两个区间相同）。
- 取出 `st[2][1] = 2`，对应深度 0，答案下标 2。

### 举例：查询区间 `[0, 3]`（长度 4）
- `k = 2`，左 `st[2][0]`，右 `st[2][0]`，都是 0。

### 举例：查询区间 `[1, 3]`（长度 3）
- `length = 3`，`log₂(3) = 1`，`k = 1`。
- 左区间：`st[1][1]`（覆盖 `[1,2]`），下标 2。
- 右区间：`st[1][3 - 2 + 1] = st[1][2]`（覆盖 `[2,3]`），下标 2。
- 比较后得到下标 2。

## 五、复杂度分析

| 阶段     | 时间复杂度 | 空间复杂度 |
| -------- | ---------- | ---------- |
| 预处理   | O(m log m) | O(m log m) |
| 单次查询 | O(1)       | -          |

其中 `m = 2n - 1`（欧拉序列长度），因此对于 LCA 问题，预处理为 O(n log n)，空间 O(n log n)。

## 六、ST 表代码逐行解释（对应前面的实现）

```python
m_len = len(euler)
LOG = m_len.bit_length()        # 相当于 floor(log2(m_len)) + 1
st = [[0] * m_len for _ in range(LOG)]

# 初始化第 0 层
for i in range(m_len):
    st[0][i] = i

# 构建更高层
for k in range(1, LOG):
    step = 1 << (k - 1)         # 2^(k-1)
    for i in range(m_len - (1 << k) + 1):
        left = st[k-1][i]
        right = st[k-1][i + step]
        # 比较深度，选较小的下标
        st[k][i] = left if depth_seq[left] < depth_seq[right] else right
```

### 为什么 `range(m_len - (1 << k) + 1)`？
因为从 `i` 开始，长度为 `2^k` 的区间右边界是 `i + 2^k - 1`，不能超过 `m_len - 1`，所以 `i ≤ m_len - 2^k`，即循环 `m_len - 2^k + 1` 次。

### 查询代码
```python
def query(l, r):
    length = r - l + 1
    k = length.bit_length() - 1      # floor(log2(length))
    left_idx = st[k][l]
    right_idx = st[k][r - (1 << k) + 1]
    if depth_seq[left_idx] < depth_seq[right_idx]:
        return euler[left_idx]
    else:
        return euler[right_idx]
```

## 七、回到 LCA 问题：ST 表的作用

在欧拉序列 LCA 中：
- `euler` 存储结点编号
- `depth_seq` 存储对应深度
- `first[u]` 存储结点 `u` 在 `euler` 中首次出现的下标

对于询问 `(u, v)`，我们先找到 `l = first[u]`, `r = first[v]`（设 `l ≤ r`），然后在 `depth_seq[l..r]` 中找最小值下标，该下标对应的 `euler` 值就是 LCA。  
ST 表使得这个 RMQ 操作变为 O(1)，因此整体查询为 O(1)（在线）。

## 八、常见疑问解答

**Q1：ST 表能否求区间和？**  
不能，因为区间和不满足可重叠性。例如 `sum[1..5]` 不能用 `sum[1..3] + sum[3..5]` 得到（会重复计算中间元素）。

**Q2：为什么不用线段树？**  
线段树可以 O(log n) 查询，且支持修改。但若不需要修改，ST 表查询更快（O(1) vs O(log n)），且代码更短。

**Q3：ST 表空间太大怎么办？**  
可以用两个较小数组滚动（如只保留 `st[k]` 和 `st[k-1]`），但查询时无法直接索引 `st[k][...]`，必须额外计算或保留所有层。在 LCA 中 `m ≈ 2n`，`log n` 在 20 左右，空间通常可接受（如 n=5e5，约 5e5×20×4 bytes ≈ 40 MB）。
